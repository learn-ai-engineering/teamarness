# 0043 — Document folders are replicated paths with independent placement

**Status:** accepted (2026-11-16)
**Refines:** ADR 0027 (Document metadata), ADR 0038 (optional folder on create), ADR 0042 (format generation 2)

## Context

A Collection can map to a flat folder under ADR 0041. Teams also need nested planning documents. Replicated Folder entities would require identities and lifecycle rules for empty folders, although the needed behavior is placement of Documents.

Metadata records with identical bytes have the same Record ID. Encoding only author, Document, and folder would prevent a later return to a folder from expressing a new move. Existing mappings also ignore subfolders: silently making those mappings recursive could share files their owner never intended to publish.

## Decision

**Placement.** Kind 12, `document.place`, carries author, Document ID, canonical folder, and a 128-bit operation identity. Its canonical layout is `TDOCS\x01`, kind byte 12, length-prefixed UTF-8 author, Document ID and folder, then 16 operation bytes. Earlier record encodings do not change. Each intentional placement gets a fresh identity; retry of an uncertain filesystem operation must reuse its original identity.

The projection uses its own greatest Order Key. Placement waits for its Document and is independent of Collection, title, archive state, and body edits. Collection moves preserve the folder. Root is `""`; folders exist through their Documents, not as entities.

**Paths.** Local ingress normalizes to NFC. Canonical records must already be NFC. Paths are slash-separated, at most eight segments and 512 UTF-8 bytes. Empty segments, dot and dot-dot segments, absolute paths (including drive-rooted paths), backslashes, and control characters are refused. Hidden paths remain valid metadata, but recursive mapping must refuse paths its scan policy or filesystem cannot represent rather than silently sanitize them. Actual disk spelling remains separate from logical folder paths.

**Caller contracts.** Snapshots and Port 1.4 listing include `folder`. UI request `documents.document.place` changes replicated placement; `documents.place.get/set` still holds only local navigation. UI and Port create accept an optional folder, validated before append. Root create remains one record. Non-root create appends create then place with the same authorized Person or Host-derived Agent. Port create returns the genesis version for revise, not a metadata version. Any failure after create is outcome-uncertain, even a certain refusal of the placement append. Neither caller automatically retries the whole create. No Agent move Port is added.

**Persistence and upgrade.** Forward-only migration 0011 adds `documents.folder`, `documents.place_order`, and `folder_mappings.recursive` with default false. State updates preserve the local mode. Format generation rises from 1 to 2. ADR 0042 re-evaluation recovers genuine retained kind-12 rows without redelivery; unopenable history keeps the stored generation retryable. Existing body bytes and file associations are unchanged. Older builds cannot open an upgraded local database. Older peers on their own databases quarantine placement until upgrade, while ordinary body edits remain compatible.

**Consent and recursive safety.** The recursive engine uses the stored mapping mode. An existing mapping needs an in-place preview and confirmation before it enables subfolders on that Installation. New mappings become recursive through their preview-confirm flow. Do not unmap/remap or clear durable bases. Before consent, tracked root files retain their last paths and body associations; new foldered Documents must not flatten into root files. A missing or unreadable root archives nothing. Preserve the existing guard when the active scan has zero eligible readable Markdown files, including deletion of its only populated subtree. Cleanup removes only empty directories Teamarness's own operation emptied, never recursively and never the root.

## Alternatives

- **Folder entities:** unnecessary identities, conflicts, and empty-folder lifecycle.
- **Extend `document.move`:** changes an existing record's encoding and semantics.
- **Deterministic placement without operation identity:** cannot express repeated returns.
- **Automatically enable existing mappings:** may share previously ignored private files.
- **Unmap and remap to enable recursion:** discards durable file state and conflicts with first-mapping rules.

## Consequences and evidence

The implementation includes metadata, migration, upgrade recovery, caller contracts, mode-selected scanning and watches, folder-scoped filenames, protected subtree refusals, hash-paired moves, safe parent creation and cleanup, and relocation recovery. Migration 0012 stores source, destination, expected hash, and operation identity until the new path is adopted. Recovery checks current placement before append and preserves pending body-write state. Refused relocation paths stay reserved rather than becoming new imports. An `invalid_folder` mapping refusal distinguishes a disk representation problem from valid logical metadata.

Existing mappings default to flat; new mappings use recursive preview reports and explicitly store recursive mode. The settings action **Enable subfolders** calls `documents.mapping.enable-recursive`. Its dry run lists incremental imports, refusals, reformatting, and required moves or exports without writing files, directories, records, or local state. Confirmation rescans under the worker's reconcile gate, rejects blocking relocation collisions and unsafe paths, applies the git warning, then updates only the local mode. Ordinary import refusals do not block activation. Existing hashes, bases, pending writes, and refusal rows stay intact. Startup reconciliation completes work after a crash following the mode commit. Repeated enable returns unchanged. Counts remain complete when report lists stop at 200 entries or reach the shared 128 KiB report budget, below the 256 KiB UI payload limit.

Settings show **Subfolders not synced**, waiting folder changes, and the enable action for legacy mappings. Before confirmation they state that imports are shared with the Workspace. Recursive mappings show **Subfolders synced**. Unsent mapping drafts and unmap behavior are unchanged. The Collection tree groups Documents by folder, preserves collapse state, and reveals the selected Document after remote placement without replacing its editor. Create supports a chosen or typed path. **Move to folder** includes root, while **Move to Collection** preserves the folder. Ordinary buttons and inputs work within the existing Package frame; no native select popover or Shell change is required. R14 and ADR 0041 describe the engine and its exact zero-eligible-files guard.

Tests in `backend/src/domain.rs`, `lib.rs`, `store/mappings.rs`, and `backend.rs` cover canonical bounds, normalization, arrival order, repeated placement, restart, v10 migration, retained-kind recovery, actor fidelity, root-only compatibility, second-append uncertainty, listing invalidation, and bounded Port payloads. The frozen `backend/tests/fixtures/ports-1.3.json` and contract comparison permit only the declared 1.4 schema additions. `folder_sync/mapping.rs` request tests cover preview purity, state preservation, recursive first mapping, bounded reports, and changed-since-preview collision, alias, symlink, unreadable-path, and git refusals. Reconciler tests cover restart immediately after activation and local consent isolation; the watcher test enables through the real request. `settings.test.ts` covers preview, cancel, blocked confirmation, git consent, drafts, and mode labels. No Core, Host, Shell, SDK, protocol, or dependency changes are needed.

`tests/system/tests/documents_folder_sync.rs` qualifies two real loopback Installations with independently enabled mappings: a nested watcher save with concurrent body edits, repeated root/folder moves, populated folder rename, safe parent cleanup, subtree archive and restore with a sentinel, the unchanged zero-files guard, and a stopped Installation's 50 nested edits plus additions, move, and deletions. Restart synchronization runs without mounting its Documents UI. A legacy-mode fixture retains real file bases while checking ignored local subfolders, no flattening, pure incremental preview, and in-place activation. Migration defaults and pending-write crash recovery remain covered at the store and reconciler seams; the system fixture does not run an older executable.

`tests/system/tests/documents_ports_proof.rs` retains 1.0 and 1.2 Consumers and adds a real 1.4 Agent Consumer that lists folders, creates at root and in a normalized folder, and revises from the returned genesis. Authenticated Core records prove the Agent signs create, place, and revise. UI controller and view tests and `npm run verify:documents-editor` cover folder controls and live-state retention under the actual frame policy. Automated evidence is local macOS qualification, not separate-network latency, Linux and Windows watchers, or a real-editor manual observation.

A crash between create and place can leave an empty root Document. It requires listing and reconciliation, not automatic create retry. Hash-only disk move detection will not promise identity for a move combined with changed content. Accepted repeat-archive and filesystem race limits remain in DELTA-023 group 11. Don's folder UI and real-editor checks belong to final Verify; automated metadata tests do not establish those observations.
