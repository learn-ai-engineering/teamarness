# Package Port Contract v1 — declaration profile

`portContract` points to one strict JSON file at most 1 MiB. The closed document has `schemaVersion: 1`, `$defs` and `contracts`; each contract has a Package-Identity-shaped independent `identity`, positive `major`, `minor`, nonempty concise `description` and `ports`. At most 32 contracts and 256 ports per file are admitted. Identity appears only once in the document. Each port has a dotted `name`, unique within its contract, a nonempty description (at most 512 Unicode scalars), `kind` (`command`, `query`, `event`), and exact schemas: commands and normal queries use `request` and `response`; live queries use `request` and `event`; events use only `event`. See `fixtures/version-1-0.json` and `schemas/port-contract.schema.json`. No other document, contract, or port fields are accepted.

The Host compiles the same restricted Draft 2020-12 JSON Schema profile as UI contracts: local `$defs` references only, no dynamic references or cycles, at most 64 levels and 16,384 schema nodes per contract; runtime payloads are bounded to 256 KiB and 64 levels. Names use the UI dotted operation-name grammar. Imperative command, noun query and past-tense event names are suggestions only; grammar warnings cannot block admission.

A minor revision may add ports and edit descriptions, but shall not remove or alter the kind or request/response/event schemas of an existing port. `check_additive_minor_documents` compares two compiled documents, including definitions reachable from existing Ports, when both versions are available. The standalone `check_additive_minor` contract-only helper rejects `$ref` schemas because it cannot inspect their definitions (the `version-1-0` and `version-1-1` fixtures exercise direct-schema comparison). This conservative v1 policy requires identical schemas for existing ports, even where a schema change might be semantically widening. A standalone Package Directory does not contain history, so its validator cannot assert historical compatibility without the prior version. Installed-set checks, availability and generation grants are separate from local declaration validity.

`packages/conversations-package/ports.json` is a real 1.3 Provider example. It declares `message.post` as a command for the Host-derived actor, `message.page` as a read-only bounded query, `messages.changed` as an empty-object, live-only projection invalidation, and, added in 1.1, `channel.list` as a query that returns the visible Channels as `{channels:[{id, name}]}`, at most 64, in the same order and with the same visibility as the Provider's own UI. The 1.0 ports kept their kinds and schemas; only descriptions changed, which `check_additive_minor_documents` verifies against the 1.0 document kept at `packages/conversations-package/backend/tests/fixtures/ports-1.0.json`. The Provider does not emit an initial event. A subscriber queries a page after subscribing and re-queries after an event or reconnection; the event is neither Message content nor a replay cursor. The Provider refuses a Person actor whose Installation does not match its own. It accepts an Agent actor as Host-derived: the Message names the Agent's key as its author and the Provider passes the actor's `principal` to its record-log 1.1 `append`, so Core signs with the Agent's key under the standing rule, or refuses with `principal_not_bound` (ADR 0030). A 1.0 Consumer that declares only the three original ports continues to work against the 1.3 Provider.

`packages/documents-package/ports.json` is a 1.2 Provider that follows the same actor rule on its `document.revise` and `document.create` commands: a Person must be this Installation, and a Host-derived Agent actor's record names the Agent's key and is appended with its `principal`, or refused as `documents.principal_not_bound` with nothing changed (ADR 0033, ADR 0038). Version 1.2 adds `document.create`, which takes `{collectionId, title}`, creates an empty Document and returns `{documentId, version}` for a first revise, and the ordinary `runtime.guide` query, so Documents is an agent-facing contract under ADR 0035. A create refuses an unknown or archived Collection and an invalid title with certainty; any later failure is uncertain, and a repeated create makes a second Document. Its 1.0 and 1.1 documents are kept at `packages/documents-package/backend/tests/fixtures/ports-1.0.json` and `ports-1.1.json`.

Version 1.2 adds `message.changes`, a read-only query backed by the same projection journal as the Conversations UI. Request `{channelId, epoch, after, limit?}` uses the epoch and decimal-string revision captured by `message.page`, not its display position or wall-clock time. The response contains at most 32 revision-ordered `events`, a `continuation`, and the sampled `highWater`. Insert events include ready content or a pending/unavailable status; removal events identify removed Messages. A Consumer acknowledges only an examined prefix, retains pending work, and requests another batch when behind. It uses the unchanged `messages.changed` notification to wake catch-up, and queries again after reconnection. `resyncRequired:true` means the saved epoch/cursor is not valid for this projection; the Consumer must choose an explicit resynchronization policy, not assume continuity or replay side effects. Neither query marks a Channel read. The 1.1 fixture and additive test preserve every earlier Port's kind and schemas.

Version 1.3 adds the ordinary `runtime.guide` query with a closed empty request and a closed response requiring bounded `markdown`. Its actual encoded response stays below 32 KiB and derives numeric advice from enforced Backend constants. The five existing operation kinds and schemas are unchanged. The guide explains the 64-Channel discovery bound, the Backend's 32-raw-row page cap beneath the unchanged 64-item schema ceiling, 32-change batches, and the 32 KiB UTF-8-byte post limit. It also specifies recovery, repeatability, error envelopes, and no automatic retry of uncertain posts. See the [Conversations Package reference](../../../packages/conversations-package/README.md). A declared consumer can retrieve guide metadata without a binding. Because this contract now has a conforming guide, bound-Agent access defaults to `port_not_enabled` even for declared Ports. The Host implements durable enablement, generic Agent discovery and lifecycle revocation, with scripted repository coverage. Independent Verify and external harness provenance, UI observations and model quality remain separate qualification. Enablement is not a compatibility bypass or a Provider setting.

## Installation admission (Host open)

After local Package Identity and declaration validation, the Host chooses a feasible installation-wide Provider graph, one Provider per contract identity. Selection runs per admission tier (ADR 0036): Team Packages choose among Team providers only, and Personal Packages are then selected with the Team providers fixed. A Personal claim on a Team-provided contract loses with `port_provider_conflict`. It retains the greatest number of persisted, still-feasible Provider choices; ties use contract identity order, then incumbent, application-bundled source, installation-local source, and Package Identity. Neither discovery order nor recent calls replace a viable incumbent. A Package losing one of its provided contracts cannot provide its other claims. Other valid claimants lose with `port_provider_conflict`; dependency-invalid claimants receive their dependency verdict. Search is limited to 4,096 explored states per connected contested component. If that ceiling is reached before selection is settled, all Provider claims in that component receive `port_graph_search_limit`, while unrelated Packages continue; the Host does not persist a provisional replacement. Selected choices are persisted in private Host metadata, never a Package Data Directory. Required consumers of missing contracts (`port_contract_missing`), absent or differently kinded ports (`port_missing`), or incompatible major/minor versions (`port_version_mismatch`) are rejected until dependencies reach a fixed point; members of required dependency cycles receive `port_dependency_cycle`. Other Packages continue. Optional absences do not reject the Consumer. An additive newer Provider minor satisfies a Consumer's older minor range; the negotiated minor is the highest in the intersection (at most the Consumer's `maxMinor`). No extra ports are granted by negotiation. The authoring catalog retains locally valid installed declarations and admission/availability diagnostics, including graph-rejected Packages; the public Host snapshot lists only admitted Packages. Workspace reconciliation never rescans registrations. A live Personal install, reload, or remove re-resolves only the Personal consumers whose selected route changed and restarts them; Team routes never change while the Host runs. Actual per-generation grants and dispatch are a separate interface. Host and SDK adapters can optionally expose bounded, payload-free process-local observations of their existing `p:` and `h:` IDs. These are not fields in a Port Contract or wire frame. A lagged observer or missing Provider terminal does not alter or prove a command outcome.
