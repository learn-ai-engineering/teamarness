# Package Port Contract v1 — declaration profile

`portContract` points to one strict JSON file at most 1 MiB. The closed document has `schemaVersion: 1`, `$defs` and `contracts`; each contract has a Package-Identity-shaped independent `identity`, positive `major`, `minor`, nonempty concise `description` and `ports`. At most 32 contracts and 256 ports per file are admitted. Identity appears only once in the document. Each port has a dotted `name`, unique within its contract, a nonempty description (at most 512 Unicode scalars), `kind` (`command`, `query`, `event`), and exact schemas: commands and normal queries use `request` and `response`; live queries use `request` and `event`; events use only `event`. See `fixtures/version-1-0.json` and `schemas/port-contract.schema.json`. No other document, contract, or port fields are accepted.

The Host compiles the same restricted Draft 2020-12 JSON Schema profile as UI contracts: local `$defs` references only, no dynamic references or cycles, at most 64 levels and 16,384 schema nodes per contract; runtime payloads are bounded to 256 KiB and 64 levels. Names use the UI dotted operation-name grammar. Imperative command, noun query and past-tense event names are suggestions only; grammar warnings cannot block admission.

A minor revision may add ports and edit descriptions, but shall not remove or alter the kind or request/response/event schemas of an existing port. `check_additive_minor_documents` compares two compiled documents, including definitions reachable from existing Ports, when both versions are available. The standalone `check_additive_minor` contract-only helper rejects `$ref` schemas because it cannot inspect their definitions (the `version-1-0` and `version-1-1` fixtures exercise direct-schema comparison). This conservative v1 policy requires identical schemas for existing ports, even where a schema change might be semantically widening. A standalone Package Directory does not contain history, so its validator cannot assert historical compatibility without the prior version. Installed-set checks, availability and generation grants are separate from local declaration validity.

`packages/conversations-package/ports.json` is a real 1.0 Provider example. It declares `message.post` as a Person-only command, `message.page` as a read-only bounded query, and `messages.changed` as an empty-object, live-only projection invalidation. The Provider does not emit an initial event. A subscriber queries a page after subscribing and re-queries after an event or reconnection; the event is neither Message content nor a replay cursor. The Provider refuses an actor whose Installation Person does not match its own. The Host-derived actor does not grant an Agent's signing authority (ADR 0026).

## Installation admission (Host open)

After local Package Identity and declaration validation, the Host chooses a feasible installation-wide Provider graph, one Provider per contract identity. It retains the greatest number of persisted, still-feasible Provider choices; ties use contract identity order, then incumbent, application-bundled source, installation-local source, and Package Identity. Neither discovery order nor recent calls replace a viable incumbent. A Package losing one of its provided contracts cannot provide its other claims. Other valid claimants lose with `port_provider_conflict`; dependency-invalid claimants receive their dependency verdict. Search is limited to 4,096 explored states per connected contested component. If that ceiling is reached before selection is settled, all Provider claims in that component receive `port_graph_search_limit`, while unrelated Packages continue; the Host does not persist a provisional replacement. Selected choices are persisted in private Host metadata, never a Package Data Directory. Required consumers of missing contracts (`port_contract_missing`), absent or differently kinded ports (`port_missing`), or incompatible major/minor versions (`port_version_mismatch`) are rejected until dependencies reach a fixed point; members of required dependency cycles receive `port_dependency_cycle`. Other Packages continue. Optional absences do not reject the Consumer. An additive newer Provider minor satisfies a Consumer's older minor range; the negotiated minor is the highest in the intersection (at most the Consumer's `maxMinor`). No extra ports are granted by negotiation. The authoring catalog retains locally valid installed declarations and admission/availability diagnostics, including graph-rejected Packages; the public Host snapshot lists only admitted Packages. Registration changes are scanned at the next Host open, not during Workspace reconciliation. Actual per-generation grants and dispatch are a separate interface. Host and SDK adapters can optionally expose bounded, payload-free process-local observations of their existing `p:` and `h:` IDs. These are not fields in a Port Contract or wire frame. A lagged observer or missing Provider terminal does not alter or prove a command outcome.
